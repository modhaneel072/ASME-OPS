# ASME Ops

ASME Ops is the ASME @ UIowa chapter's operations workspace: projects and milestones, work orders, assets, teams and users, locations, categories, vendors, comments, files, notifications, saved filters, global search and an operations report, with organization scoping, twelve scoped roles and an immutable audit trail.

This repository contains only ASME Ops. It is one Flask application (package `asme/`) plus a React + TypeScript single-page app (`apps/ops-web/`) that is built into `static/ops/` and served at `/app`. Everything else the server exposes is JSON under `/api`, and `/` redirects to `/app`. There is no public website, member/admin portal, kiosk, landing page or server-rendered HTML sign-in page.

## Layout

```
app.py                 WSGI entry point (gunicorn app:app)
manage.py              upgrade / seed / evaluate / reconcile / worker / serve / routes
asme/
  __init__.py          create_app() factory
  config.py            typed Settings - every ASME_* var resolved once, validated at boot
  ops/                 ASME Ops: models (ops_* tables), permission registry + policy engine,
                       services, serializers, validation, storage
  blueprints/
    ops/               /api/v1 endpoints for ASME Ops (auth, session, users, teams, locations,
                       categories, assets, vendors, projects, work orders, comments, attachments,
                       saved filters, notifications, changes, reports, search, setup)
    ops_app.py         serves the SPA at /app, redirects / to /app, /healthz
    api_v1.py          legacy JSON API (items, checkouts, print requests, events, bookings, onboarding)
    api_legacy.py      legacy /api endpoints
  auth/                session handling, role + entitlement decorators, login rate limiter
  models/ services/    legacy domain models and services (see "Legacy backend services" below)
  integrations/        calendar (google/outlook adapters), mail, assistant
  events/ jobs/        in-process domain event bus, transactional outbox + worker
apps/ops-web/          React + TypeScript frontend (Vite, Vitest, Playwright)
static/ops/            built frontend bundle (generated; never edit by hand)
migrations/            Alembic (Flask-Migrate)
scripts/               generate_ops_docs.py, outlook_sync_doctor.py, setup_bambu_print.ps1
tests/                 pytest suite (app factory, in-memory SQLite); tests/ops for ASME Ops
docs/                  architecture, API reference, permissions matrix, deployment, plans
models.py, services/   compatibility shims -> asme.models, asme.integrations.assistant
```

**Layering rule.** Blueprints parse, authorize and serialize. Services own transactions and business rules and are the only place that touches `db.session`.

## Quick start (Windows PowerShell)

Backend:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
Copy-Item .env.example .env        # sets ASME_ENV=development
python manage.py upgrade           # migrate to head + defaults (admin account, organization, roles, default location, categories)
python app.py                      # http://127.0.0.1:5000
```

Frontend (`apps/ops-web`):

```powershell
cd apps/ops-web
npm ci
npm run dev        # http://127.0.0.1:5173/app, proxies /api to the Flask server on :5000
npm run build      # type-checks and writes the bundle to ../../static/ops, served by Flask at /app
```

On this Windows machine `npx` and the npm script shims can be unreliable; run the tool binaries through `node` instead:

```powershell
node ./node_modules/typescript/bin/tsc -b
node ./node_modules/vite/bin/vite.js          # dev server
node ./node_modules/vite/bin/vite.js build    # bundle -> static/ops
```

Open `http://127.0.0.1:5000` (it redirects to `/app`) and sign in with `ASME_DEFAULT_ADMIN_EMAIL` / `ASME_DEFAULT_ADMIN_PASSWORD` from `.env`. The system ships with no example data: projects, teams, people, locations and assets are entered by the chapter (Setup Center walks through it). Change the default admin password after the first sign-in.

## Routes

- `/` redirects to `/app`.
- `/app/*` serves the SPA shell (never cached). Signed-out screens: `/app/auth/login`, `/app/auth/forgot-password`, `/app/auth/reset-password?token=...`.
- `/api/v1/*` is the JSON API (`docs/api.md`, generated by `python scripts/generate_ops_docs.py`); unknown `/api` paths return the JSON error envelope.
- `/healthz` and `/api/v1/health` are unauthenticated health checks.

`python manage.py routes` prints every URL rule with its endpoint.

## Accounts

Sign-in, sign-out and every account flow run inside `/app` against `/api/v1`:

- **Sign in** - `/app/auth/login` with e-mail or username (`POST /api/v1/auth/login`).
- **Forgot password** - `/app/auth/forgot-password` calls `POST /api/v1/auth/forgot-password`, which always answers `{sent: true}` for a well-formed address (it never reveals whether an account exists) and, when the address belongs to an active account, e-mails a single-use, expiring link to `/app/auth/reset-password?token=...`.
- **Reset password / accept an invitation** - `/app/auth/reset-password?token=...` checks the token with `GET /api/v1/auth/reset-password/<token>` (purpose `invite` for accounts that have never signed in, otherwise `reset`) and sets the password with `POST /api/v1/auth/reset-password`. `POST /api/v1/users/invite` returns an `invite_url` of this form for the accounts it creates.
- **Change password** and **edit profile** - Settings > Profile (`POST /api/v1/auth/change-password`, `PATCH /api/v1/session/profile` for name, major, graduation year and phone).

Forgot-password e-mail is sent through the outbox, so production needs `ASME_SMTP_USER` / `ASME_SMTP_PASS` (with `ASME_SMTP_HOST` / `ASME_SMTP_PORT`); without them nobody receives a link. Set `ASME_PUBLIC_BASE_URL` to the public origin so e-mailed links never depend on the request `Host` header. In development without SMTP the reset link is logged as a warning.

Existing accounts keep working: legacy `admin` maps to Chapter Administrator, `team_leader` to Team Lead and `member` to Full Member on first sign-in.

## Environment variables

`.env.example` lists every variable. The ones that matter most:

| Variable | Purpose |
|---|---|
| `ASME_ENV` | `development`, `production` or `testing` |
| `ASME_SECRET_KEY` | session and download-token signing; the default refuses to start in production |
| `ASME_DATABASE_URL` | PostgreSQL in production; SQLite `instance/inventory.db` in development |
| `ASME_AUTO_MIGRATE` | migrate + seed at boot (on in development, off in production) |
| `ASME_APP_BOOT_TOKEN` | optional; defaults to a value derived from `ASME_SECRET_KEY` (stable across workers and restarts). Change it to sign everyone out |
| `ASME_SESSION_COOKIE_SECURE` | `1` behind HTTPS |
| `ASME_PUBLIC_BASE_URL` | origin for password reset and invite links |
| `ASME_SMTP_HOST` / `ASME_SMTP_PORT` / `ASME_SMTP_USER` / `ASME_SMTP_PASS` | outgoing mail (forgot-password) |
| `ASME_TRUSTED_PROXY_COUNT` | proxies that append to `X-Forwarded-For`, for rate limiting |
| `ASME_DEFAULT_ADMIN_EMAIL` / `ASME_DEFAULT_ADMIN_PASSWORD` | account created by `manage.py upgrade` |
| `ASME_UPLOAD_ROOT` / `ASME_UPLOAD_MAX_MB` / `ASME_STORAGE_BACKEND` | private attachment storage (outside `static/`) |
| `ASME_OPS_POLL_SECONDS` / `ASME_OPS_DOWNLOAD_TTL_SECONDS` | change-feed polling and signed download lifetime |
| `ASME_OUTBOX_WORKER` | `0` disables the in-process outbox worker |

| Setting | development | production |
|---|---|---|
| `ASME_AUTO_MIGRATE` | on | **off** - run `python manage.py upgrade` as a release step |
| default `ASME_SECRET_KEY` | warning | **refuses to start** |

## Deployment

The frontend bundle must be built (`apps/ops-web` -> `static/ops`) and committed, or built in CI, because the Python hosts do not run Node. Production deploys run migrations for you:

- **Procfile** - `release: python manage.py upgrade`
- **render.yaml** - `startCommand: python manage.py upgrade && gunicorn ...` (health check `/healthz`)
- **Elastic Beanstalk** - `.ebextensions/03_migrate.config` (`leader_only`); health check `/healthz`

See `docs/deployment.md` for the full release checklist and smoke test.

## Background work

`outbox_jobs` is a transactional outbox: a service commits the job row together with the domain write, and an in-process worker thread (started on the first request; `ASME_OUTBOX_WORKER=0` to disable, or run `python manage.py worker` as a separate process) executes it with retry and backoff. ASME Ops uses it for password reset e-mail (`auth.password_reset`: the worker looks the account up, mints the token and sends the mail, so the HTTP request does the same work for every address) and the hourly `ops.work_order.scan` (overdue and due-soon notifications, missed milestones).

## Legacy backend services

The earlier chapter platform's public website, member/admin portal, kiosk and NFC check-in screens and standalone sign-in pages have been removed. Its backend is still present, without any user interface, because production databases may hold members, inventory items, checkouts and attendance records:

- tool checkout inventory with the append-only stock ledger (`asme/services/inventory.py`)
- 3D print requests (`asme/services/fabrication.py`)
- attendance (`asme/services/attendance.py`)
- room scheduling mirrored to Google Calendar or Outlook (`asme/services/scheduling.py`, `asme/integrations`, `OUTLOOK_CALENDAR_SETUP.md`)
- Launchpad onboarding (`asme/services/onboarding`)

Their models (`asme/models`), migrations, events, jobs and the JSON blueprints `asme/blueprints/api_v1.py` and `asme/blueprints/api_legacy.py` remain registered and covered by the backend test suite. Whether to keep, migrate into ASME Ops or retire these services and their data is a pending decision (see `docs/implementation-status.md`).
